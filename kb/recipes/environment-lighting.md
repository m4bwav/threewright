# Environment lighting

## Goal

`MeshStandardMaterial` and other lit materials render pure black with no light and no `scene.environment` at all. Give every scene one or the other. `RoomEnvironment` through `PMREMGenerator` lights PBR materials plausibly with zero network requests; an HDR/EXR file through the same generator gives a specific, art-directed look when one is available.

## Code

No-download environment, for a chart, a product thumbnail, or anywhere a specific HDR is not worth the bytes:

```js
import * as THREE from 'three';
import { RoomEnvironment } from 'three/addons/environments/RoomEnvironment.js';

const pmrem = new THREE.PMREMGenerator(renderer);
const room = new RoomEnvironment();
let envTarget = pmrem.fromScene(room, 0.04); // a render target; keep it to dispose later
scene.environment = envTarget.texture;
room.dispose(); // its boxes and materials are only needed while generating

// Replacing the environment at runtime (a variant switch, a day/night cycle):
// dispose the old render target, not only its texture, or GPU memory climbs.
function setEnvironment(sourceScene) {
  const old = envTarget;
  envTarget = pmrem.fromScene(sourceScene, 0.04);
  scene.environment = envTarget.texture;
  old.dispose();
}
// pmrem.dispose(); // once you are done generating environments
```

A specific HDR environment, for a hero product shot or a branded scene:

```js
import * as THREE from 'three';
import { HDRLoader } from 'three/addons/loaders/HDRLoader.js'; // the current name since r180

const pmrem = new THREE.PMREMGenerator(renderer);
new HDRLoader().load('studio.hdr', (hdrTexture) => {
  scene.environment = pmrem.fromEquirectangular(hdrTexture).texture; // keep the render target too if you will swap it
  scene.background = scene.environment; // optional: shows the HDR blurred to PMREM resolution
  hdrTexture.dispose(); // the source equirect texture; pmrem.fromEquirectangular() copies what it needs
});
```

On `WebGPURenderer`, `await renderer.init()` before calling `pmrem.fromScene()`/`fromEquirectangular()`: the `*Async` PMREM methods (`fromSceneAsync`, `fromEquirectangularAsync`, `fromCubemapAsync`) are deprecated since r181 in favor of the synchronous versions after init.

## Verify

- `tw check <page>` reports `environment true` or `false` in its scene summary line. With lit materials and neither lights nor an environment it prints `lit materials but no lights and no scene.environment: meshes will render black`. Check this first for a black scene, before color space or camera position.
- If the page regenerates its environment, read `renderer.info.memory` before and after several swaps (`tw check <page> --eval "swaps(5)"` with a page helper): geometries and textures must stay flat.
- A `tw shot` then confirms the look (warm or cool, bright or dim) once the text check rules out a missing environment.
- Verified 2026-09-26 on Windows 11, Chrome 153 headless, RTX 5060 Ti (WebGL), three 0.186.1 from node_modules, with two spheres (metal and rough) and ACES tone mapping. RoomEnvironment page: `environment true`, `result: OK`. HDR page, with a 128x64 Radiance file generated by a Node script: `environment true · background texture`, `result: OK`, three files served locally. The same page with no environment printed the two warnings above and `PROBLEMS FOUND`. Swaps: the original snippet regenerated with `.texture.dispose()` grew by one geometry and one texture per swap (15/3 to 20/8 over five swaps); the fixed code stayed at `geometries 14, textures 3` over five swaps. `tw lint` found 0 errors and 0 warnings. The shots showed a chrome sphere reflecting the room, and the HDR sky and ground on both spheres.
