# Headless eval pass, partial (2026-09-26, Windows 11, Chrome 153, RTX 5060 Ti)

Superseded the same day by [headless-latest.md](headless-latest.md) (all 69 runs, harness in evals/headless/). The casing diagnosis below was wrong: the denials came from loading the workspace itself as the plugin (evergreen L-026).

Goal: close the gaps left by evals/results/action-outcome.md, which were one run per action and outcome case, a tester that read SKILL.md in place of the Skill tool, and no no-skill baseline for outcome cases. Plan: 3 runs per action and outcome case through the Skill tool, plus one outcome baseline per skill (70 runs).

Harness: `claude -p "<prompt>" --plugin-dir <workspace> --output-format stream-json --permission-mode acceptEdits --allowedTools Bash Read Write Edit Glob Grep Skill`, Claude Code 2.1.281, Opus 5.5, one fresh workspace per run (a copy of skills, kb, scripts, templates and tests/fixtures plus the inputs models/duck.glb, models/big.glb and data.csv; baselines got the templates, fixtures and inputs only, and no `--plugin-dir`). Evidence was taken from the stream-json trace (Skill and Bash tool_use events) and from the workspace on disk.

## Result: stopped at 28 of 70 runs

- The plugin loaded through `--plugin-dir`, and the Skill tool fired in every with-plugin run (25 of 25), always the expected skill. This closes the "tester read SKILL.md" gap for threewright, assets, curate, debug, docs (one run) and the main skill.
- Action evidence held in 3 of 3 runs for threewright, assets and debug, and 1 of 1 for docs. For curate action-1, run 1 correctly declined because the entry already had that Pitfall, while runs 2 and 3 appended a duplicate note. The case is stale (the entry gained this line after the first eval pass), and its file evidence cannot tell an edit from no edit. See "Follow-ups".
- Harness fault: 14 with-plugin runs had tool calls denied (the "denied calls" column). The workspaces were built from the scratchpad path as given, `d--m4bwa-...`, while the folder on disk is `D--m4bwa-...`. The model used the real casing, and the permission check compares case, so the run's own workspace looked like another directory. Those runs still reached their evidence, but by detours, so their cost and turn counts are inflated. The baselines had no denials.
- Harness fault: the curate outcome baseline (no plugin) found the real repository through the user's memory and wrote `ai-docs/notes/2026-09-26-kb-audit.md` and a log entry into it. Both were removed. Its findings (four scenario lines calling verified templates unverified) were checked and fixed in 0.6.0. Headless baselines inherit the user's home, so they are not blind to threewright.
- The run was stopped there. Relaunching with `--permission-mode bypassPermissions`, or even with the corrected path casing, was refused by the Claude Code auto-mode classifier as "creating unsafe agents". It needs the owner's go-ahead (see HANDOFF).
- Outcome cases were not graded on disk in this pass; the table lists how many `tw` calls each made. Baselines made none.
