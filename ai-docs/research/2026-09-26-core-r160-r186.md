# Three.js core r160 to r186: verified change record

Date: 2026-09-26
Track: three.js core, r160 to r186. This is the source for the threewright stale-API linter and the core knowledge base entries.
Status: first pass, verified. Every release, symbol and path below was checked against at least one primary source: the installed `three` 0.186.1 (`node_modules/three`), the npm registry and tarballs, the source at each release tag (raw.githubusercontent.com), the Migration Guide wiki, or the GitHub release notes. Claims marked "unverified" were not confirmed by a primary source.

## Summary

- Latest is r186: npm `three` 0.186.1 (2026-09-24). 0.186.0 shipped 2026-09-08. The 0.186.1 patch changes four files on the WebGPURenderer path only (`NodeMaterialObserver`, `VelocityNode`, `NodeBuilder`, `Geometries`). No API changes.
- Release cadence changed. Releases were monthly up to r182 (2025-12-10). Since then they come about every two months: r183 (2026-02-18), r184 (2026-04-16), r185 (2026-06-25), r186 (2026-09-08). GitHub tag and release dates follow the last patch release, so use npm dates.
- The legacy layer is gone. WebGL 1 and `WebGL1Renderer` were removed in r163. The UMD builds `build/three.js` and `three.min.js` were removed in r161. `outputEncoding`, `texture.encoding`, `sRGBEncoding` and `LinearEncoding` were removed in r162. `physicallyCorrectLights` was removed in r160 and `useLegacyLights` in r165.
- WebGPURenderer moved into core in r167 with the `three/webgpu` entry. `three/tsl` got its own build (`build/three.tsl.js`) in r171. Post-processing effect nodes left core for `three/addons/tsl/display/` in r170. `PostProcessing` was renamed `RenderPipeline` in r183. WebGPURenderer falls back to WebGL 2 automatically (since r156).
- r181 deprecated the async render methods (`renderAsync`, `clearAsync`, `hasFeatureAsync`, `initTextureAsync`, the PMREM `*Async` methods). Since r181 `render()` throws if the renderer is not initialized. `computeAsync()` is not deprecated in the source, even though the Migration Guide lists it.
- r182 made `PCFShadowMap` soft and deprecated `PCFSoftShadowMap` for WebGLRenderer. In r186 both renderers log a warning and switch `PCFSoftShadowMap` to `PCFShadowMap`. The constant is still exported.
- r183 deprecated `Clock` in favour of `Timer` (in core since r179) and added `docs/llms.txt`.
- r186 deprecated the CommonJS build (`build/three.cjs` is now a 631-byte stub), removed every minified build, and renamed `Source` to `TextureSource`. It added native Gaussian splats (`GaussianSplat` plus five loaders, WebGPURenderer only), `SunLight` with cascaded shadows (both renderers), `OITPassNode`, `SSAONode`, `VXGINode`, `DirectRenderPipeline`, `compileComputeAsync()`, `resetState()` on WebGPURenderer and `Object3D.dispose()`.
- The r186 manual still calls WebGPURenderer "still in an experimental state" and says WebGLRenderer "is still maintained and the recommended choice for pure WebGL 2 applications".
- Corrections to the seeds: the UMD builds were removed in r161, not r160 (0.160.1 still ships them). `computeAsync` is not deprecated. The old aliases for `applyMatrix`, `THREE.Math`, `ImageUtils.loadTexture`, `gammaFactor`, `addAttribute` and friends all stopped working together in r141, when `Three.Legacy.js` was emptied.
- Lint rules: 121 stale-API rules (89 error, 32 warn) and 13 companion rules. Every rule compiles, matches its positive samples and rejects its negative samples. Across all 607 official r186 examples no stale-API rule fires except one warning on a page title. On 30 official examples from r110 the rules fire 75 times.

- `computeAsync()` has no deprecation warning in r181 to r186. The r181 Migration Guide text says "renderAsync() and computerAsync() ... have been deprecated", but the source never warns. In r186 `compute()` called before init even says "Try using .computeAsync() instead".

## Lint rules

How to read the tables:

- `pattern` is a JavaScript regex source. Compile it with no flags (add `g` to collect every match). In the tables every `|` inside a pattern is written `\|`, as GitHub tables require. Replace `\|` with `|` before compiling. No pattern contains a literal backslash followed by a pipe.
- Run patterns on the whole file text after blanking comments (`stripComments` in `scripts/lib/lint.mjs` does this). A message that starts with "(file)" marks a rule that needs the whole file, because it combines two facts, such as a WebGPURenderer and an EffectComposer in one file.
- `release` is the first release where the severity applies. For error rows it is the release where the code breaks or silently does nothing. For warn rows it is the release that deprecated the API. The message names the other release when there is one.
- A project pinned below `release` is not wrong today. Report those hits as upgrade notes, not errors.

## Implications for threewright

**Linter data.** Regenerate `kb/rules/lint-rules.json` from the two tables above. Its `since` and `removed` fields map to the "deprecated" and "broken since" releases named in each message. The current file (51 rules, read 2026-09-26) disagrees with the verified record in these places:

- `umd-build` (`build/three(?:\.min)?\.js\b`) misses the cdnjs form `ajax/libs/three.js/r128/three.min.js`, which is the exact "WRONG" example in the r186 `llms.txt`. Use the pattern in this file.
- `buffer-geometry-aliases`: deprecated r144, removed r154 (the file says 125 and 144). The `Edges`, `Wireframe`, `Parametric` and `Text` prefixes are not in the core alias list (unverified for addons).
- `add-attribute`, `apply-matrix`, `three-math`: removed r141 (the file says r125). `apply-matrix` was renamed in r113 (the file says r115).
- `gamma-settings`: `gammaInput` and `gammaOutput` removed r112, `gammaFactor` removed r136, shims gone r141 (the file says removed r128).
- `physically-correct-lights`: removed r160 (the file says r155).
- `pcf-soft-shadow-map`: deprecated r182 for WebGLRenderer (the file says r186).
- `draco-exporter-parse`: `parse()` throws since r185, so it is removed, not deprecated.
- `sky-is-sky`: `.isSky` is still valid on the WebGL `Sky` class. Only `SkyMesh.isSky` is deprecated. Require `SkyMesh` in the file or drop the rule.
- `webgl1-renderer`: WebGL 1 was deprecated in r153.
- Missing: every id in the tables above that the file lacks, for example `text-geometry-height`, `shader-chunk-encodings`, `buffer-attribute-update-range`, `tsl-fx-import-from-core`, `tsl-removed-imports`, `display-p3-core`, `webgl1-context`, `three-nodes-entry`, `timer-addon-path`, `transform-controls-add`, `composer-without-output-pass`, `texture-loader-without-srgb` and `tsl-importmap-needs-webgpu`.

**Version awareness.** Read the project's three version (`node_modules/three/package.json`, or the `three@x.y.z` in an import map URL). Apply error and warn only when that version is at or past `release`. Otherwise print "breaks when you upgrade to rNNN".

**Deprecation scanner.** The HANDOFF idea of scanning `@deprecated` markers finds deprecations, with two gaps. First, many markers carry no release: the JSDoc tag says only `@deprecated` and the release sits in a trailing `// @deprecated rNNN` comment or in the message (`Matrix3`, `KTX2Loader`, `DRACOLoader`, the async renderer methods). Parse both forms. Second, a marker scan cannot see removals or renames without an alias: minified builds, `LottieLoader`, the Sky `up` uniform and `LightProbeGrid` (now the WebGPU class) left no marker in r186. Those come from the Migration Guide and from diffing tags. r186 has 109 markers outside `libs/`.

**Runtime hints.** `tw check` should map these console messages to the same rule ids, so static and runtime checks agree: "PCFSoftShadowMap has been removed", "has been deprecated", "has been renamed", `THREE_CJS_DEPRECATED`, ".render() called before the backend is initialized" and "WebGPU is not available, running under WebGL2 backend" (the last one is information, not an error).

**Knowledge base entries** (each with `applies_to: r186` and a last verified date):

- `kb/topics/releases-r160-r186.md`: the section 1 table plus the cadence change.
- `kb/topics/deprecations-r186.md`: the section 2 table, including the `computeAsync` note.
- `kb/topics/removed-apis.md`: the section 3 table, ordered by "broken since".
- `kb/topics/color-and-light-defaults.md`: the section 4 table, the PI factor for legacy scenes, and which textures get `SRGBColorSpace`.
- `kb/topics/webgpu-tsl.md`: the section 5 timeline, the build table, the r186 additions and the manual's "experimental" wording.
- `kb/topics/imports-r186.md`: section 6 with both import maps and the gotchas.

**Templates.** Both existing templates pass all 134 rules (checked 2026-09-26). `templates/html-importmap/index.html` pins 0.186.1 on jsDelivr and uses `Timer` and the default `PCFShadowMap`. `templates/html-webgpu/index.html` already uses the four-entry import map, `await renderer.init()`, `RenderPipeline` and `bloom` from `BloomNode.js`. New templates should run the linter in CI. A splat template must use WebGPURenderer. No template may reference a `.min.js` build.

**Skill guidance.** Default to WebGLRenderer unless the task needs TSL, compute or WebGPU-only features (splats, `OITPassNode`, SSGI, VXGI). The r186 manual still calls WebGPURenderer experimental. For WebGPU: import from `three/webgpu` and `three/tsl`, wait for init, build post-processing with `RenderPipeline`, and never use `ShaderMaterial`, `onBeforeCompile` or `EffectComposer`. For both: physical light units, `SRGBColorSpace` on color maps, `Timer` instead of `Clock`, `PCFShadowMap`.

## Claims likely to change

- The r186 to r187 section of the Migration Guide already describes unreleased changes on the dev branch: PMREMs based on cube render targets with `CubeUVReflectionMapping` removed (materials will look slightly different), `WeakRef` and `FinalizationRegistry` inside both renderers, the XR camera derived from the first sub camera, `WebGLRenderer.setViewport()` and `setScissor()` no longer scaling by pixel ratio when a render target is bound, and `pixelationPass()` `pixelSize` accepting only numbers.
- Scheduled removals: `VTKLoader` and `DRACOLoader.setDecoderConfig()` in r194, `LWOLoader` in r195. The CommonJS stub "will be removed in a future release".
- Since r141 the Migration Guide says legacy code is removed "after ten releases". By that rule the r181 async methods would go around r191, `Clock` and `PostProcessing` around r193, and `Source` and the CommonJS stub around r196. This is a projection, not a published plan.
- `computeAsync()` may still be deprecated for real, as the r181 Migration Guide text says.
- The manual's "still in an experimental state" wording for WebGPURenderer, the limits of `WebGLNodesHandler`, and WebXR on the WebGPU backend (new in r185) are all moving.
- The Gaussian splat API was renamed twice before r186 shipped (`GaussianSplatMesh`, `PLYGaussianSplatLoader`). Expect more changes.
- Release cadence: about two months since r182, down from monthly.
- The Migration Guide is a wiki and gets edited. Its r162 entry says `WebGLMultipleRenderTargets` was removed, while the source kept a warning shim until r171.
- Node's require(esm) behavior decides whether the CommonJS stub works in older Node versions.
